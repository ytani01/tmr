## きっかけ

`TODO-015` で `README.md` と `docs/User.md`, `docs/Developer.md` を
整備したあと、`TODO-016` でアラームの外部コマンドが入った。
`TODO-016` の reviewer が `CLAUDE.md` のずれを 3 点指摘したのが直接の
きっかけで、それに限らず文書全体を実装と照らし直すことにした。

指摘されていたのは次の 3 点。

- 「アラームの鳴らし方は `AlarmParams(count, sec1, sec2)`」— `cmd` が増えた
- 「停止の合図は `alarm_active` フラグ 1 つ（スレッド側もメインループ側も
  見ている）」— コマンドの経路ではスレッド側が見ない
- 値の検証の節に `cmd` の扱いが無い

## 決めたこと

**`CLAUDE.md` と `docs/Developer.md` の書き分け。** 同じ設計の説明が
両方にあったので、**`docs/Developer.md` を正**とし、`CLAUDE.md` には
作業のたびに要る要点と落とし穴だけを置くことにした。`CLAUDE.md` は
毎回コンテキストに読み込まれるので、短く保つ方が得になる。

## 分担の振り返り

**verifier が見つけたこと。** 記述と実装のずれは 1 件も無かった。
ただし「`docs/User.md` は終了コードに触れていない」という参考指摘があり、
これは実際に文書へ反映した。**ずれを見つけなかったこと自体が成果**で、
特に幅の表（7 段階）と `COMMAND LIST` は、目で読んだだけでは
「合っているはず」で済ませていた所を、モックを組んで文字単位で
突き合わせている。設定ファイルの実地確認は、1 回目の報告で
「テストコードの読解に留めた」と正直に書いてあったので追加で依頼し、
7 項目すべて実地で確かめさせた。**やらなかったことを書いてあったから
追加依頼できた**ので、報告に「確かめられなかったもの」の節を求めるのは
効いている。

**wording が見つけたこと。** 直すべき 2 件と好みの範囲 7 件。
用語のゆれ（「サイクル／巡／巡回」「戻る／フォールバック」）を
文書をまたいで拾えたのは、4 つを一度に読ませた効果。
敬体・常体の乱れは無いという確認も返ってきた。
一方で、README の見出しを英語のままにするかどうかは判断を保留して
管理者に投げてきており、**これは正しい切り分け**だった（利用者に聞いて
「日本語にする」と決まった）。

**見込みとの食い違い。** 見込みどおり `verifier + wording` で足りた。
実装を変えない項目なので `implementer` と `reviewer` は立てず、これも
過不足なかった。ただし**両担当のモデルを定義の `haiku` から Sonnet 5 に
上げた**。文書と実装の突き合わせは「一致しているか」の判断が要るので、
ここは上げて正解だった（幅の表を再現するスクリプトを自分で組み立てている）。

**次に同じ規模でどう組むか。** 料金の 69% が main で、うち大半は
文書 4 本と実装の読み込み。**次は調査そのものを分けてよい**。
今回 main は「ずれの一覧を作る」ために `timer.py` 全体・`cli.py`・
`view.py`・`pomodoro.py` と 4 つの文書を読んでおり、その多くは
verifier が後から独立に読み直している。**先に verifier を「実装と
文書の突き合わせ表を作る」担当として走らせ、その報告を受けて main が
直す**方が、同じ読み込みを 2 回しなくて済む。ただし今回のように
「どう書き分けるか」を決める作業が主なら、main が実装を把握して
いないと判断できないので、書き分けの方針が決まっていない項目では
今回の組み方でよい。

verifier と wording を**同時に走らせたのは効いた**（wording には
「ファイルを直さず案を報告するだけ」と指示し、verifier が照合中の
本文が動かないようにした）。
