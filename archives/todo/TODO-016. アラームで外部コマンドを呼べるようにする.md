## きっかけ

ベル（`\a`）だけでは気づかないことがある。音声ファイルの再生や
デスクトップ通知を、任意のコマンドで呼べるようにしたかった。

## やったこと

`AlarmParams` に `cmd` を足し、指定されたらビープの代わりに外部コマンドを
実行する。CLI は `--alarm-cmd` / `--cmd`（`timer` / `pomodoro` 共通）。
設定ファイルの `alarm-cmd` からも指定できる。

着手前に利用者と決めたこと:

- `cmd` を指定したらビープは鳴らさない（置き換え）。未指定なら従来どおり
- タイムアップ時に 1 回だけ実行する（`count` 回は繰り返さない）
- シェル経由（`shell=True`）。パイプやリダイレクトを書けるようにするため
- ポモドーロは全フェーズ共通で 1 つ（work / break で分けない）
- コマンドを実行したあともキー入力を待つ。従来のビープ（既定 999 回＝
  実質鳴り続ける）と体感を揃える
- 失敗しても（コマンドが無い、非ゼロ終了）ログに残して続行する

**レビューを受けて、途中で作りが 2 度変わった。**

1 度目 — `subprocess.run` で呼ぶだけの実装に対し、reviewer が
「`[Q]` を押してアラームを止めても、コマンドが終わるまで `main()` が
返らない」（実測 `sleep 3` で 3.21 秒）と指摘した。利用者が
**「コマンドも止める」**と決めたので、`Popen` + `start_new_session=True`
\+ `os.killpg`（SIGTERM → 1 秒 → SIGKILL）に作り替えた。
併せて子の入出力を端末から切り離した（stdin は `DEVNULL`、
stdout / stderr はログへ）。

2 度目 — その作り替えが 2 つの回帰を生んだ。どちらも reviewer が
実測で見つけた。

- `start_new_session=True` により、端末が送る `SIGINT` が子に届かなくなり、
  **`Ctrl-C` で子プロセスが残るようになった**（1 巡目のコードでは
  死んでいた。`start_new_session` の有無だけを変えた比較で確定）
- 出力を `PIPE` に全部ためるので、`--cmd "yes"` で **python 自身が
  OOM kill された**（50MB の出力で RSS 31.9MB → 318.6MB）

ここで利用者が線引きを決めた。**「変なコマンドを書いた側の責任」に
なるものは直さず、`docs/User.md` に注意として書く。**

- OOM（出力が大量に出るコマンド）→ 直さない。許容する
- `&` でバックグラウンドにすると止まらない → 直さない
- POSIX 専用になること → Windows は想定しないので何もしない
- `Ctrl-C` の残骸 → **直す**。`aplay` を指定した普通の使い方でも、
  `Ctrl-C` のあと音が鳴り続けるため

`Ctrl-C` の対応は `main()` で `KeyboardInterrupt` を捕まえて
`stop_alarm_cmd()` を通す形にした。ただし後始末に最大 3 秒かかるので、
その間の 2 度目の `Ctrl-C` で `SIGKILL` の前に抜けてしまう。
`try/except KeyboardInterrupt: pass` で包むだけでは直らず、
**後始末の間の `SIGINT` マスクに加えて、アラームのスレッドも `SIGINT` を
止めた状態で起動する**必要があった（スレッドが受け取るとマスクを
素通りする）。

マスクを戻すのに `SIG_UNBLOCK`（無条件の解除）を使っていたのを、
`SIG_BLOCK` の戻り値を `SIG_SETMASK` で戻す形に管理者が直した。
呼ぶ側が `SIGINT` を止めている場合に、tmr が勝手に解除しないため
（`Timer` をライブラリとして直接使う経路）。

`--cmd ""`（空文字・空白のみ）は、他のオプションと揃えて click の
usage error（終了コード 2）にした。`AlarmParams.__post_init__` の
`ValueError` はライブラリ経路用として残してある（二重の作り。TODO-012）。

## 確かめたこと

- テスト 191 件、lint 4 つ（`ruff format` / `ruff check` /
  `basedpyright` / `mypy`）とも通る
- `pty.fork()` の下で実測。**ビープ / コマンド × `Ctrl-C` 1 回・2 回・
  `[Q]` のすべてで即終了し、子プロセスの残骸が無い**
- 呼ぶ側が `SIGINT` を止めた状態で `Timer` を通しても、抜けたあと
  ブロックが保たれている
- `--cmd ""` / `--cmd "   "` が終了コード 2（`timer` / `pomodoro` の両方、
  設定ファイル経由も）
- `README.md` は help 出力を載せていないので変更不要（実測で照合）

## 残ること

見送ると決めたもの。`docs/User.md` に注意として書いてある。

- 出力が大量に出るコマンドを指定すると、tmr がメモリ不足で落ちる
- `&` でバックグラウンドにするような書き方をすると、キーを押しても
  すぐに止まらない（tmr 自体が止まって見える）
- `os.killpg` / `SIGKILL` / `start_new_session` は POSIX 専用。
  Windows は想定しないので、コードも文書も対応していない
- アラームのコマンドは `SIGINT` を止めた状態で起動される（スレッドの
  マスクを継ぐため）。子は別セッションにいて端末の `Ctrl-C` を受けず、
  tmr が `SIGTERM` → `SIGKILL` で止めるので停止手順には影響しない

`CLAUDE.md` の設計記述のずれ（`AlarmParams` のフィールドが増えた、
`alarm_active` が唯一の合図ではなくなった、値の検証）は **TODO-017** で直す。

## 分担の振り返り

分担にした理由と各担当の報告は
[archives/agents/TODO-016/](../agents/TODO-016/) にある。

**各担当が何を見つけたか。**

- **reviewer が全ての重い問題を見つけた。** `[Q]` を押しても返らない、
  `Ctrl-C` の残骸が 2 巡目の回帰であること、`yes` での OOM、
  `&` で固まること、テストが開発機のプロセスを撃ちうること。
  いずれも**実測付き**で、pty を組んで確かめている
- **verifier は 4 巡すべて「合格」しか出さなかった。** 指示した項目
  （テスト、lint、help と文書の照合、コマンド例の再現）は正確に
  確かめているが、**指示していない壊れ方は 1 つも見つけていない**。
  `Ctrl-C` の残骸も OOM も、verifier の 4 回の「合格」をすり抜けた
- **implementer は 1 度、reviewer の案が効かないことを実測で示した**
  （`try/except` で包むだけでは 2 度目の `Ctrl-C` を止められない）。
  言われたとおりに直して終わりにしなかった点は良い
- **管理者（main）は、自分が出した指示が回帰を生んだことに気づけなかった。**
  「コマンドも止める」「出力をログへ」はどちらも私の指示で、
  そのまま `Ctrl-C` の残骸と OOM になった。気づいたのは reviewer

**見込みと食い違ったのはなぜか。**

編成（implementer + verifier + reviewer）は見込みどおりで、
**足りていた**。食い違ったのは**巡数**で、5 巡した。原因は、
「外部コマンドの面倒をどこまで見るか」を**決めずに着手した**こと。
指摘のたびに対症療法を重ね、そのたびに新しい回帰が出た。
料金 $31.1 の大半（implementer 43% + reviewer 32%）は、この巡り直しに
消えている。

**次に同じ規模の項目をやるなら。**

- **子プロセスを扱う項目では、着手前に「どこまで面倒を見るか」を
  利用者と決める。** 今回の 3 巡目以降は、その線引き（「変なコマンドを
  書いた側の責任」）が決まった時点で一気に収束した。**同じ線引きを
  1 巡目の前に置けば、2 巡で終わった**
- **verifier に「指示した項目の確認」以上を期待しない。** 4 回とも
  合格を出した事実は、担当の質ではなく**役割の設計**の問題。
  壊れ方を探すのは reviewer の仕事だと割り切り、verifier は
  Haiku のまま（料金の 3%）でよい
- **reviewer を惜しまない。** 料金の 32% を使ったが、見つけたものの
  重さに見合っている。**シグナルやプロセスを扱う変更では、
  巡ごとに必ず reviewer を通す**
- 管理者が自分でコードを直したとき（今回の `SIG_SETMASK`）は、
  **その箇所を名指しして担当に見せる**。今回はそうした
