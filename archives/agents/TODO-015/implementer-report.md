## design.md から変えた点と理由

1. **図 1 のフェーズ名を実物に合わせた。** design.md は
   `WORK 1/4` / `SHORT BREAK` / `LONG BREAK` だったが、`pomodoro.py` の
   `phases()` が作る題は `WORK:1/4` / `SHORT_BREAK:1/4` /
   `LONG_BREAK:4/4`。画面に出る文字列と図を一致させた。
   長い休憩の番号が `4/4` になることも実装どおり。
2. **図 1 の点線ラベルを「繰り返す」に短縮。** design.md の
   「quit するまで繰り返す」は、直後の散文と重複するため。
   `[Q]` で終わること、`-c` で変わることは図の下に 2 行で書いた。
3. **図 2・図 3 の桁を実測値に差し替えた。** design.md の例は桁が
   実物と違っていた（項目の間は空白 1 個、`rate` の値自体が
   `%5.1f%%` で先頭に空白を持つ、`limit` と `title` の間も空白 1 個）。
   下の「確かめたこと」を参照。
4. **図 2 の説明を、指示線＋表の 2 段にした。** design.md は指示線の
   右側に説明文を並べる形だったが、`remain` の指示線が 66 桁目に来るため
   行が 100 桁近くになる。指示線には項目名だけを置き、意味は表にした。
5. **図 3 の幅を 70/50/40/30/25/15/10 の 7 段にした。** 実測すると
   幅 80 の行が 80 桁ちょうどになり、行頭の `NN │` を足すと 85 桁に
   なるため 80 を落とした。幅 20 は幅 15 と同じ出力になるので落とした。
6. **`Developer.md` に「値の検証」「端末の後始末」の節を足した。**
   design.md の節構成には無いが、`CLAUDE.md` にある設計の意図のうち
   3 文書のどこにも入らなくなるため。
7. **図 5 の状態遷移図から角括弧を外した**（`[P]` → `P`）。
   `stateDiagram-v2` では `[*]` が開始・終了の記号なので、遷移ラベルの
   角括弧を避けた。キー表記としての角括弧は `User.md` 側にある。
8. **README の見出しから `== ` / `=== ` の接頭辞を外した。**
   Markdown の見出しに `==` を重ねる書き方は現 README 独自のもので、
   新規の 2 文書と揃わないため。**元に戻すなら指示がほしい**（判断が要る点）。

## 確かめたこと

- **help 出力**: `uv run tmr --help` / `uv run tmr timer --help` /
  `uv run tmr pomodoro --help` を `COLUMNS=80` で実行し、出力をそのまま貼った。
  現 README の内容と一致していた。
- **COMMAND LIST**: `Timer.fn_help()` を `enable_next=True` /
  `False` の両方で実行し、`[N], [ENTER] : Next.` の行が
  `enable_next=True` のときだけ出ることを確認した。`User.md` に貼ったのは
  `enable_next=True`（ポモドーロ）の出力。
- **図 2・図 3 の表示例**: `blessed.Terminal` を `MagicMock`（`term.width`
  に数値）にして `TimerView.display()` を直接呼び、`click.echo` /
  `click.style` / `time.strftime` を patch して素の文字列を取り出した。
  `elapsed=630` / `t_limit=1500`（42.0%、10m30s、残り 14m30s）、
  日時は `2026-09-08 14:03:21` に固定。図 2 の指示線の桁位置も、
  各列の値の長さから計算して置いた。使い捨てスクリプトはリポジトリ外
  （scratchpad）に置き、残していない。
- **落ちる順**: 実測した各幅の出力が
  `date` → `time` → `elapsed` → `rate` → `limit` → `pbar` →
  `title` の順に消えることを確認し、表にした
  （`state` は通常空なので幅を食わない）。
- **mermaid**: 5 枚すべてを `@mermaid-js/mermaid-cli` 11.17.0 で
  レンダリングし、SVG が出ることを確認した

  エラー図になっていない）。

  `{"executablePath":"/usr/bin/chromium","args":["--no-sandbox"]}` を

- **リンク**: `docs/User.md` / `docs/Developer.md` / `docs/fig1.png` /

## 残る懸念

  管理者の判断。
- **`docs/fig1.png` の内容は確認していない**（画像なので、現在の表示と
  ずれている可能性がある）。TODO-015 では「新しいスクリーンショットは

  仕様から書いた。`tmr` 側で検証していないので、不正な色名を渡したときの
  挙動には触れていない。**範囲外だが、`click.style()` が `TypeError` に
  なるはずで、CLI で弾いていない**。

  進む」は、既定のアラーム回数（999 回・約 33 分）を前提にした書き方。
  鳴り終われば自動で次へ進むが、実用上は起きないので書いていない。
