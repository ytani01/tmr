# TODO-017 の分担

文書だけを変える項目なので、`implementer` と `reviewer` は立てなかった
（コードの分岐が変わらないため）。main が本文を直し、確認と推敲を分けた。

| 担当 | モデル | 依頼した内容 | 報告 |
|---|---|---|---|
| main | Opus 5 / effort high | 実装と 4 文書の突き合わせ、書き分けの決定、本文の修正 | — |
| verifier | Sonnet 5（定義は haiku） | 文書に書かれた手順・コマンド例・help 出力・幅の表を**実際に動かして**照合 | [verifier-report.md](verifier-report.md) |
| wording | Sonnet 5（定義は haiku） | 4 文書の文面の推敲（**直さず案を報告**） | [wording-report.md](wording-report.md) |

## この分担にした理由

- **手順の再現を main が兼ねない。** 書いた本人は「書いたとおり」と
  読んでしまう。`README.md` / `docs/User.md` には、そのまま試せる
  コマンドと help 出力の貼り付けがあるので、再現は必ず分ける
- **モデルを定義の `haiku` から上げた。** 文書と実装の突き合わせは
  「一致しているか」の判断が要る。実際、verifier は `TimerView` に
  幅を変えたモックを渡すスクリプトを自分で組んで、幅の表 7 段階を
  再現している
- **wording には本文を直させなかった。** verifier が同じファイルを
  読んで照合している最中に本文が動くと困るため、推敲案を報告ファイルに
  書かせ、採否は main が判断した

の「分担の振り返り」にある。
