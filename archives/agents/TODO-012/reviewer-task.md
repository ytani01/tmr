# TODO-012 reviewer への依頼

## 目的

TODO-012（0 分・0 サイクルを指定すると壊れる）の実装差分を、規約と設計に
照らしてレビューする。**コードは直さない。** 見つけたことを報告する。

## 背景

再現していた現象:

| 指定 | 現象 |
|---|---|
| `tmr timer 0` | `TimerClock.rate` で `ZeroDivisionError` |
| `tmr timer -- -1` | 即満了扱いでアラームが鳴り続け、止まらない |
| `tmr pomodoro -c 0` / `-c -1` | `phases()` が何も yield せず `while True` を回り続けて固まる |
| `tmr pomodoro -w 0` | `timer 0` と同じ `ZeroDivisionError` |

決めた方針は **「CLI で弾き、ライブラリ層でも防御する」**。
0 を「即満了」として動かすことはしない。

## 対象

`git diff`（未コミット）の全体。7 ファイル。
実装者の報告は `archives/agents/TODO-012/implementer-report.md`。

## 特に見てほしい点

これは**分岐と条件式が変わる項目**なので、「テストが通る」ことではなく
「分岐の意味が正しいか」を見てほしい。

- **境界値の向き**が正しいか。`t_limit <= 0` で弾く／`cycles < 1` で弾く／
  `FloatRange(min=0, min_open=True)`（0 は不可、0 より大きければ可）／
  `IntRange(min=1)`。**`-w 0.1` のような小さい正の小数は通らないといけない**
- `phases()` をジェネレータから「検証してから `_phases()` を返す普通の関数」に
  分けた変更が、**呼び出し側（`PomodoroTimer.run()`）から見て等価か**。
  型注釈 `Iterator[...]` のままでよいか
- `TimerClock.__init__` で `ValueError` を上げることの**波及**。
  `Timer.__init__` 経由でこの例外が出る経路、`TerminalContext` の中で
  例外が出たときの端末の後始末（`terminal.py`）に問題が無いか
- CLI で弾いているので、ライブラリ層の `ValueError` が
  **通常の利用でトレースバックとして利用者に見えてしまう経路が残っていないか**
- 例外メッセージが分かりやすいか
- 追加されたテストが、**実際にその分岐を突いているか**（通るだけの
  テストになっていないか）。特に `phases()` のテストが固まらない作りか
- `CLAUDE.md` の規約（行長 78、ログ規約、設計の記述との整合）に沿っているか
- **`CLAUDE.md` / `README.md` の記述が、この変更で古くなっていないか**
